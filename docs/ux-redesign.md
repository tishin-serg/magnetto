# UX-переработка Magnetto — MGB-09

Дата проверки: 6 сентября 2026. Статус: локальная реализация, не развёрнута.
Рабочий каталог: `C:/Users/xataa/Documents/magnetto`.
Временный worktree `magnetto-ux` использовался только для изоляции разработки;
после проверки изменения перенесены в основной каталог, worktree удалён.

## Область аудита

Изучены маршруты команд, LLM и callback, `/start` и `/help`, поиск TMDb/JacRed,
подбор фильма, сезоны/серии/качество/озвучка, magnet и выбор места, выбор файлов,
подтверждение размера, настройки, задачи/пауза/продолжение, три медиатеки,
ссылки на файлы, единичное удаление, полная очистка и обработка ошибок Telegram.
Аудит основан на коде и воспроизведении сценариев в локальных тестах, а не на
наблюдении за реальными пользователями. Частотность действий — продуктовая
гипотеза: поиск, загрузки и просмотр используются чаще обслуживания хранилищ.

## Главные проблемы

1. Девять равнозначных пунктов; очистка рядом с поиском. Постоянной клавиатуры нет.
2. `/help` повторяет меню, `/library` объединяет Home/VPS, но не S3. Переходы расходятся.
3. На старте перечисляются возможности, в поиске объясняются внутренние алгоритмы.
4. Настройки размножают сообщения. «Отмена» вводит в заблуждение при немедленном сохранении.
5. Ожидание числа конфликтует с переходом в другой сценарий. Ошибки и старые экраны
   часто заканчиваются сообщением без следующего действия.
6. Ошибка Home/S3 маскируется под пустую медиатеку. Задачи показывают enum-статусы.
7. Выбор места может обработаться дважды. Выбор файлов переключается повторным
   нажатием, не проверяет владельца/актуальную стадию задачи и не имеет выхода.
8. Полная очистка запускается при выборе хранилища. Старое подтверждение удаления
   не ограничено временем и может относиться к уже изменившемуся файлу.

## Новая структура

```text
Постоянная клавиатура
┌───────────────┬────────────────┐
│ 🔎 Поиск      │ 📥 Загрузки    │
│ 🎬 Медиатека  │ ⚙️ Настройки   │
└───────────────┴────────────────┘

Медиатека → Домашний ПК / Сервер VPS / Облако S3
          → Свободное место
          → Очистка → хранилище → явное подтверждение
Помощь (/help или inline-меню) → просмотр на iPhone
```

Вложенные действия используют inline-кнопки; переходы редактируют сообщение.
Основные разделы всегда доступны через постоянную клавиатуру после `/start`.
На списках хранилищ «← Медиатека» ведёт к выбору хранилища, на карточке файла —
к его списку. «Главное меню» открывает первый уровень. «Отмена» прекращает заявку
до запуска; «Выбрать позже» сохраняет ожидающую задачу и выбор файлов.
Команда `/cancel` прекращает ввод, но не отменяет уже запущенные загрузки.

Стартовый текст:

> 🎬 Magnetto
>
> Найду и скачаю фильмы и сериалы. Готовые файлы — в медиатеке.
>
> Отправь название или выбери «🔎 Поиск» для подсказок.

Система текстов: действие/состояние сначала, детали ниже, восстановление кнопкой.
Сохраняется обращение на «ты». Основные emoji закреплены за разделами;
новые экраны содержат не больше двух действий в строке.

## Пользовательские пути

Под действием здесь понимается нажатие кнопки или отправка сообщения; ввод символов
не считается отдельно. Счёт сравнивает одинаковую исходную точку, а не скорость API.

| Цель и исходная точка | Было | Стало |
| --- | --- | --- |
| Открыть настройки из вложенного экрана с возвратом в меню | Меню → настройки: 2 | Постоянная кнопка: 1 |
| Поставить загрузку на паузу из другого вложенного раздела | Меню → задачи → пауза: 3 | Загрузки → пауза: 2 |
| Запустить подготовку сезонной раздачи из результатов поиска | Раздача → подтверждение сезонного набора → место: 3 | Раздача → место: 2 |
| Изменить число в уже открытых настройках | Параметр → число: 2, новое сообщение | Те же 2, обновляется исходный экран |
| Открыть выбранное хранилище из главного меню | 1 | Медиатека → хранилище: 2 |
| Полностью очистить хранилище из главного меню | Очистка → хранилище: 2 | Медиатека → очистка → хранилище → подтверждение: 4 |

Последние два пути намеренно длиннее: обслуживание убрано с первого уровня,
необратимое удаление требует осознанного подтверждения. Поиск обычным текстом,
команды и автоматический подбор по сохранённым условиям сохранены.

## Что изменено в коде

- `TelegramKeyboardFactory`: постоянная клавиатура, компактный первый уровень,
  меню медиатек, помощь, единые подписи возврата, восстановление из пустых состояний.
- `TelegramLlmCommandRouter`: точные кнопочные маршруты до числового ввода и LLM;
  `/start`, `/menu`, `/cancel`; очистка контекста при переходе.
- `MenuCallbackHandler`: разделение пустого и недоступного Home/S3, единый вход
  из `/library`, краткий старт и поиск, редактирование настроек по message ID.
- `MovieDownloadConfirmationService`: возврат после ввода в тот же экран,
  исправление ошибки на месте, явное немедленное сохранение, срок ввода и выход.
- `TaskOverviewService`: русские состояния, короткие кнопки, возобновление выбора файлов.
- `FileSelectionCallbackHandler`: проверка владельца/стадии, последовательная
  обработка выбора, новые `file:set` задают желаемое состояние; старые `file:toggle`
  продолжают поддерживаться. Ошибка нехватки места сохраняет кнопки выбора.
- `DownloadTargetSelectionCache`: атомарное потребление заявки; чужой просмотр
  больше не удаляет заявку владельца. Выбор места имеет действующую отмену.
- `MediaCleanupCallbackHandler`: токены полной очистки, одноразовость, срок две минуты,
  привязка к чату/сообщению. Старые callback выбора хранилища только открывают подтверждение.
- `FileDeletionConfirmation`: небольшое общее хранилище подтверждений отдельного
  файла. Home/S3 сверяют снимок файла и прекращают операцию после отмены/истечения.
- `TelegramMessageService`: истёкший callback не прерывает вывод экрана; известная
  ошибка недоступного сообщения восстанавливает экран новой отправкой. Другие ошибки
  не превращаются автоматически в повторную отправку результата операции.
- Поиск обновляет сообщение ожидания результатом или ошибкой. Роутер callback и
  обработчик входящих сообщений предлагают восстановление после исключения.

Новых таблиц, внешних сервисов и миграций БД нет. Используются существующие
Spring-компоненты; локальные подтверждения намеренно теряют силу после рестарта.
Проверены базовые возможности [Telegram Bot API](https://core.telegram.org/bots/api):
reply keyboard для входа в разделы, inline keyboard для действий, редактирование
сообщений и answerCallbackQuery. Новые Rich Messages и WebApp не требуются.

## Осознанно сохранено

- Схема доставки, retry, очередь, лимиты размера и алгоритмы поиска/подбора:
  это бизнес-логика; UX-переработка не должна менять выбранные файлы или маршрут доставки.
- Подтверждение скачивания и повторное подтверждение превышения размера:
  скачивание расходует диск и трафик; этот шаг сообщает последствия.
- Исторические сообщения о завершении операций и прогресс действующих загрузок:
  они нужны для понимания результата и не удаляются ради чистоты чата.
- Настройка Infuse/WebDAV остаётся в помощи: она нужна для конкретного способа просмотра.
- Нативный Telegram UI; WebApp и дополнительный onboarding не добавлены.
- При блокировке бота Telegram не доставит даже сообщение об ошибке. После
  разблокировки `/start` восстанавливает меню; нельзя обещать обратную связь во время блокировки.

## Ограничения, требующие отдельного наблюдения

Частотность действий и удобство формулировок пока не подтверждены пользовательской
аналитикой. Поиск/списки зависят от внешних сервисов; переработка не гарантирует
их доступность. Подтверждения и кэши текущих сценариев хранятся в памяти одного
процесса. Существующая выдача последних задач остаётся общей для разрешённых чатов,
как в исходном продукте; изменение модели совместного доступа — отдельное решение.
Сериализованная обработка выбора файлов рассчитана на текущий небольшой бот;
при росте нагрузки её следует разделить по задачам, сохраняя атомарность.
